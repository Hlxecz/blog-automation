## Windows 앱 다운로드

[H.Dev Studio 0.8.0 다운로드](https://github.com/Hlxecz/blog-automation/releases/tag/v0.8.0)에서 `HDev-Studio-0.8.0-win-x64.exe`를 받아 실행하세요. 설치가 필요 없는 Windows 64비트 앱입니다.

처음 실행하면 **티스토리 로그인**을 누릅니다. 로그인한 계정의 블로그를 자동으로 찾아 글과 카테고리를 불러옵니다. 블로그가 여러 개면 사용할 블로그를 선택하세요. **도움말 · AI 연결**에서 Codex 또는 Claude Code를 선택하고 본인 계정으로 로그인하세요. [자세한 사용 안내](docs/USAGE.md)를 참고하세요.

연결 후 로그인 버튼에는 **블로그 이름 ▾**이 표시됩니다. 이름을 눌러 블로그를 선택하거나 로그인 상태를 다시 확인할 수 있습니다.

## 실제 사용 화면

2026-09-23 기준 실제 앱 화면입니다. README 설명용 글·코드 사진·카테고리를 사용했습니다. 맨 위 대표 이미지는 콘셉트 일러스트이며, 아래 화면은 앱을 실행해 직접 캡처했습니다.

### 1. 사진과 메모로 시작하거나, 글을 직접 쓰기

왼쪽은 **글의 재료**, 오른쪽은 **편집·미리보기** 공간입니다. 사진을 모으고 글을 확인하는 과정을 한 작업실에서 이어갑니다.

![사진·참고자료·메모와 카테고리·표지·글 미리보기를 함께 보여주는 실제 작업실](docs/assets/workspace.png)

| 시작 방법 | 사용 순서 |
| --- | --- |
| 캡처로 글 만들기 | 사진 업로드 → 주제·작업 메모 입력 → 카테고리 선택 → **내 말투로 초안 만들기** |
| 기존 글 붙여넣기 | **직접 작성하기** → 문단 칸에 붙여넣기 → 필요한 칸 다듬기 |
| 처음부터 직접 쓰기 | **직접 작성하기** → 소제목·문단·코드 등을 추가하며 작성 |

사진 아래 **참고자료**에 블로그·문서·공개 노션 링크를 최대 5개 넣을 수 있습니다. **자료 읽기**로 내용을 확인한 뒤 초안에 활용합니다. 사진 없이 직접 쓰는 것도 가능합니다.

### 2. 원하는 칸만 AI로 다듬기

**편집**을 누르면 글이 문단·소제목·사진·코드 등의 칸으로 나뉩니다. 직접 내용을 고치거나, AI에게 선택한 부분의 표현을 다듬도록 요청할 수 있습니다.

1. 다듬을 칸에 글을 직접 쓰거나 붙여넣습니다.
2. 필요하면 상단 요청란에 `초보자가 쉽게 이해하도록 중복 표현을 줄이고, 편한 존댓말로 다듬어줘`처럼 원하는 방향을 적습니다.
3. 아래 세 가지 방법 중 하나로 실행합니다.

| 범위 | 누르는 곳 | 바뀌는 부분 |
| --- | --- | --- |
| 한 칸 | 해당 칸 오른쪽 **✦ 글 다듬기** | 그 칸의 문장만 |
| 여러 칸 | 원하는 칸의 체크박스 → **선택한 칸 다듬기** | 체크한 칸의 문장만 |
| 전체 | **전체 선택** → **선택한 칸 다듬기** | 다듬을 수 있는 모든 칸의 문장 |

아래는 **두 문단만 선택한 상태**입니다. 선택한 칸은 파란 테두리로 표시되고, 상단에서 선택 개수를 확인할 수 있습니다.

## 주요 기능

- 사진 업로드, 순서 변경, 작업 메모
- Codex / Claude Code CLI 선택, 설치·로그인 도움말, 이미지 분석과 초안 생성
- 기본 블로그용 프롬프트 보존, 카테고리별 글쓰기 지침과 [공개 블로그 구성을 참고해 개선한 예시 5종](docs/WRITING-PROMPT-RESEARCH.md)
- 사진 없는 직접 작성, 붙여넣은 글의 칸별·선택·전체 AI 다듬기와 되돌리기
- 제목·본문·태그 편집과 미리보기
- 편집 항목 드래그 이동과 항목 사이에 문단·사진·코드·표 추가
- 참고자료 링크 최대 5개, 공개 노션 본문 읽기와 직접 붙여 넣기
- 자동 목차, 팁·주의 상자, 목차 아래 GitHub 정보 카드
- 기존 사진에서 표지 선택 또는 별도 표지 업로드
- 티스토리 카테고리 불러오기, 하위 분류 중심의 선택 목록, 글별 선택 보관과 해당 분류로 발행
- 로컬 초안 보관, 용량 확인, 글 단위 삭제
- 로그인한 계정의 블로그 자동 연결, 공개 글 목록과 로그인된 글 관리 화면
- 검토 후 **티스토리에 발행** 버튼으로 사진 업로드부터 공개 게시까지 실행

현재 버전은 [package.json](package.json)에서 관리합니다. [버전별 변경 내역](CHANGELOG.md)과 [자세한 사용법](docs/USAGE.md)을 참고하세요.

## 개발 실행

Windows 64비트, Node.js 22 이상이 필요합니다.

```powershell
npm ci
npm run setup
```

데스크톱 앱에서는 티스토리 로그인 후 내 블로그를 선택합니다. 웹 모드에서는 생성된 `tistory.config.json`의 `blogUrl` 또는 앱의 설정 화면에 주소를 입력합니다. 0.8.0부터 사용자 요청으로 H.Dev Log의 6,408자 말투 프로필을 기본 지침에 포함합니다. **내 말투 → 기본 블로그용 프롬프트**에서 확인하고 수정할 수 있습니다. `setup`을 다시 실행해도 기존 설정은 보존합니다.

각 사용자는 자신의 티스토리 계정과 선택한 AI의 CLI 계정으로 로그인합니다. 로그인한 계정의 블로그 선택은 글 목록·카테고리·발행 대상에 함께 반영됩니다. 기존 초안과 사진은 보존합니다.

```powershell
npm start          # 웹 개발 화면
npm run desktop    # Electron 앱: 티스토리 발행 지원
```

앱의 **도움말 · AI 연결**에서 **Codex** 또는 **Claude Code**를 선택하세요. 설치·로그인 명령을 복사하고 연결을 확인할 수 있습니다. 선택은 이 PC에 저장되며 초안 생성과 말투 분석에 함께 적용됩니다. 각 CLI에 본인 계정으로 로그인하며, 앱에 API 키를 입력할 필요는 없습니다. 사진·메모·말투 지침과 분석할 공개 본문은 선택한 제공사에 전송되고 해당 계정의 요금·사용량 정책이 적용됩니다. [AI 연결 방법](docs/USAGE.md#ai-연결-방법)을 참고하세요.

## 검사와 배포용 EXE

```powershell
npm run release:check
npm test
npm run test:desktop
npm run test:categories
npm run test:writing
npm run test:setup
npm run build:exe
```

배포용 파일은 `dist/<버전>/`에 생성합니다. 같은 버전의 EXE가 있으면 덮어쓰지 않습니다. 개발 중 확인은 `npm run desktop`을 사용하고, EXE는 배포할 때 만듭니다.

**로컬 EXE는 최신 버전 하나만 보관합니다.** 버전별 소스는 Git 커밋과 태그로 관리하며, 필요할 때 해당 버전을 내려받아 다시 빌드합니다. 사용자 사진·초안은 빌드 정리 대상에 포함하지 않습니다.

버전 올리기, 배포 파일 확인, GitHub 등록 절차는 [버전·배포 관리](docs/RELEASING.md)에 정리했습니다.

## 자료와 저장소

사진·초안·로컬 말투 원문·개인 설정·로그·로그인 자료·EXE는 `.gitignore`로 제외합니다. 사용자가 배포를 요청한 기본 프롬프트 사본은 `config/style.example.md`에 포함합니다. EXE를 GitHub에 배포할 때는 저장소 코드에 넣지 않고 Releases에 첨부합니다.

배포 EXE의 기본 블로그 주소는 미설정 상태이며 로그인한 계정에서 블로그를 선택합니다. 기본 프롬프트에 등장하는 H.Dev Log의 글 주소는 문체 참고자료이며 로그인·발행 대상 설정이 아닙니다. 0.8.0는 이전의 짧은 기본 지침을 수정 없이 쓰는 경우에만 백업 후 새 기본 지침으로 교체합니다. 사용자가 수정한 프롬프트와 카테고리별 지침은 유지합니다.

앱 자료는 기본적으로 `%APPDATA%/H.Dev Studio/workspace`에 보관합니다. 메뉴 **작업실 → 자료 폴더 열기**에서 실제 위치를 확인할 수 있습니다. EXE 교체 후에도 자료를 유지하며, 티스토리 로그인은 앱을 다시 실행할 때 필요합니다.

GitHub용 자동 검사·수동 빌드 설정을 포함합니다. 공개 Release를 자동으로 만들지는 않습니다.
