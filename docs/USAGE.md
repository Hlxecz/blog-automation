# H.Dev Studio 사용 안내

개발 캡처와 메모로 내 말투의 초안을 만들고, 편집·미리보기 후 **티스토리에 발행** 버튼으로 공개 게시하는 Windows 앱입니다.

## 사용법

1. `HDev-Studio-<버전>-win-x64.exe`를 실행합니다. 설치가 필요 없는 Windows 64비트 앱입니다. 직접 빌드한 파일은 `dist/<버전>/`에서 찾을 수 있습니다.
2. 처음 실행한 PC라면 자동으로 뜨는 **내 블로그 설정**에 본인의 `https://블로그이름.tistory.com` 주소를 저장합니다. 앱 재시작 없이 반영되며, 사이드바나 작업실 메뉴의 **내 블로그 설정**에서 언제든 변경할 수 있습니다. **도움말 · AI 연결**에서 사용할 CLI를 선택하고 아래 [AI 연결 방법](#ai-연결-방법)에 따라 로그인합니다. **로그인 / 글 관리**에서 티스토리에도 로그인합니다.
3. 사진을 업로드하고 주제·메모를 적습니다. PNG/JPEG/WebP, 한 장 10MB, 한 글 20장까지 지원합니다.
4. 필요한 경우 **글쓰기 · 발행 카테고리**를 먼저 고르고 **내 말투로 초안 만들기**를 누릅니다. 해당 분류의 글쓰기 지침이 적용됩니다. 제목, 태그, 문단, 코드, 사진 설명과 순서를 편집하고 미리보기로 검토합니다.
   - 초안 위 **표지 · 대표 이미지**에서 **사진에서 선택** 또는 **표지 업로드**를 누릅니다. 표지는 즉시 로컬 저장하며, 새로 업로드한 표지는 글의 재료 목록과 별도로 보관합니다.
   - 선택한 사진을 본문 맨 위로 배치합니다. 이미 본문에 있던 사진은 설명을 유지하며 앞쪽으로 옮기므로 중복 추가하지 않습니다. **선택 해제**를 누르면 원래 본문 순서와 첫 사진을 사용하는 자동 표지로 돌아갑니다.
5. **티스토리에 발행**을 누르면 현재 편집을 먼저 보관하고, 사진 업로드 → 본문·태그 입력 → 공개 발행을 진행합니다. 추가 발행 확인 팝업은 없습니다.
6. 공개된 제목·본문·사진을 확인하면 앱에 **발행 완료**와 글 링크가 표시됩니다.
7. 공간을 비우려면 **보관한 글 → 해당 글의 삭제** 또는 작업실 상단 **삭제**를 누릅니다. 글 제목과 정리할 용량을 확인한 뒤 **이 PC에서 영구 삭제**를 누르면 해당 글의 사진 원본·메모·모든 입력 버전의 초안·편집 이력·발행용 사본을 지웁니다. 티스토리 게시글은 유지하며, 작성·발행 중인 글은 완료 후 삭제할 수 있습니다.

발행 대상은 자료 폴더의 `tistory.config.json`에 있는 `blogUrl`입니다. `npm start`는 프로젝트의 설정을, `npm run desktop`은 아래 안내된 개발 모드 자료 폴더의 설정을 사용합니다. 여러 블로그를 글 목록에 추가해도 발행 대상은 자동으로 바뀌지 않습니다. 카테고리는 아래 **발행 카테고리 선택**에서 지정하며, 기본 선택은 **카테고리 없음**입니다. 기존 글 수정은 **로그인 / 글 관리**의 티스토리 화면에서 합니다.

## 발행 카테고리 선택

- `your-blog.tistory.com`은 공용 템플릿의 예시 주소입니다. 본인 주소를 저장하기 전에는 로그인 창·카테고리 조회·발행 대상으로 사용하지 않습니다. 로그인한 계정과 글을 발행할 블로그 주소는 별도로 설정해야 합니다.
- 작업실의 글 미리보기 상단에서 **카테고리 불러오기**를 누릅니다. 초안을 만들기 전부터 선택할 수 있습니다. 데스크톱 앱이 현재 발행 대상 블로그의 **글 관리 → 보기 → 카테고리별 보기** 목록을 읽습니다. 로그인 화면이 나오면 로그인하세요. 새 글 편집기를 열지 않으며, 목록 확인 과정에서 글을 저장하거나 발행하지 않습니다.
- **글쓰기 · 발행 카테고리**에서 `Java`, `C`, `PHP`처럼 글을 넣을 분류를 선택하고 **초안 보관**을 누릅니다. 하위 분류가 있는 `Language` 같은 상위 항목은 생략하고, 하위 분류가 없는 단독 항목은 표시합니다. 같은 이름이 겹칠 때만 `Java (Language)`처럼 상위 이름을 붙입니다. 선택은 글별로 저장되며, 초안을 다시 생성해도 유지됩니다.
- 기본 선택은 **카테고리 없음** 하나입니다. 그대로 두면 분류 없는 글로 발행합니다. 실제 발행에는 선택한 항목의 번호와 전체 상위 경로를 사용합니다.
- 티스토리에서 분류를 추가하거나 이름을 바꿨다면 **목록 새로고침**을 누르고 다시 선택하세요. 삭제되었거나 이름·상위 분류가 바뀐 항목, 다른 블로그의 항목은 발행 전에 중단합니다.
- 카테고리 목록은 이 PC에 보관됩니다. 목록을 다시 읽지 못해도 기존 선택은 지우지 않습니다. `npm start`의 웹 화면은 보관된 목록만 사용할 수 있으며 새 목록 읽기와 바로 발행은 데스크톱 앱에서 지원합니다.
- 실제 편집기의 카테고리 메뉴와 공개 글의 카테고리 링크를 확인해 연결했습니다. 외부 접속 없는 자동 검증으로 저장·선택·발행 연결을 확인하며, 검증용 글을 실제로 공개 발행하지는 않습니다. 스킨에서 글의 카테고리 표시를 없애면 발행 결과 확인이 불확실해질 수 있습니다.

## 초안 순서 바꾸기·중간에 내용 넣기

- 초안의 **편집**을 누르면 문단·소제목·사진 등이 항목별로 표시됩니다.
- 항목 왼쪽의 점 여섯 개 손잡이를 누른 채 끌고, 파란색 **여기에 놓기** 선이 보이는 위치에서 놓습니다. 기존 ↑·↓ 버튼도 사용할 수 있으며, 손잡이에 키보드 초점을 둔 뒤 방향키로 이동할 수도 있습니다.
- 항목 사이 또는 맨 앞·맨 뒤의 **＋ 여기에 추가**를 누르고 문단·소제목·코드·목록·사진·비교 표를 선택합니다. 사진은 선택 창에서 골라 해당 위치에 넣습니다.
- 편집한 내용은 **미리보기**로 확인한 뒤 상단 **초안 보관**으로 저장합니다. 직접 선택한 표지는 기존과 같이 미리보기와 발행 본문의 맨 위에 배치됩니다.

## 목차 아래 GitHub 정보 카드

- 글 미리보기 상단 **GitHub 카드**를 누르고 아이콘, 주제 분류, 주제, 링크 주소·이름과 설명을 입력합니다. 예를 들어 `📚 / Java Collection / Stack & Deque`와 관련 코드의 GitHub 주소를 넣을 수 있습니다.
- **카드 추가**를 누르면 회색 바탕과 파란 링크의 카드가 목차 바로 아래에 표시됩니다. 목차가 없는 글에서는 본문 맨 위에 표시됩니다. 링크는 새 창으로 열립니다.
- 같은 버튼을 다시 눌러 수정하거나 **카드 빼기**로 제거합니다. **HTML 복사**로 카드 코드를 따로 가져올 수도 있습니다.
- **초안 보관**을 누르면 글과 함께 저장됩니다. 새 자료로 초안을 다시 만들어도 직접 설정한 카드는 유지되며, 발행 본문에도 포함됩니다.

## 글에 사용할 참고자료

- 사진 목록 아래 **참고자료**에 HTTPS 링크를 넣고 **추가**를 누릅니다. 글마다 최대 5개를 자동 보관하며 × 버튼으로 뺄 수 있습니다.
- **자료 읽기**를 누르면 AI 초안을 생성하기 전에 제목·읽은 글자 수·본문 미리보기를 확인할 수 있습니다. 읽기 결과도 글과 함께 보관합니다.
- **내 말투로 초안 만들기**를 누르면 최신 공개 본문을 다시 읽고 사진·메모와 함께 참고합니다. 일반 웹페이지는 자료별 최대 10,000자, 공개 노션은 최대 60,000자를 사용하며 길이 제한에 걸리면 표시합니다. 읽기 결과와 확인 시각은 초안의 검토 메모에도 남깁니다.
- 노션은 페이지의 나머지 부분과 접힌 항목까지 읽고 제목·목록·표·코드의 순서를 유지합니다. 하위 페이지나 연결된 다른 문서는 필요한 주소를 각각 추가하세요. 사진 속 내용은 별도로 업로드한 캡처를 통해 분석합니다.
- 비공개 노션이나 자동으로 읽기 어려운 페이지는 **필요한 내용 직접 붙여 넣기**를 펼쳐 내용을 입력하세요. 입력한 내용이 있으면 링크 접속 대신 해당 내용을 사용합니다. 로그인이 필요한 자료를 앱이 자동으로 열지는 않습니다.
- 읽지 못한 자료는 링크 아래에 표시하며 해당 본문 없이 초안을 만듭니다. **사진에 담기지 않은 이야기**에 적은 URL은 자동으로 수집하지 않으므로 참고자료 칸에 추가하세요.
- 링크나 내용을 바꾸면 다음 초안 생성부터 반영합니다. 참고자료 목록은 작성용 자료이며 발행 본문에 링크 목록을 자동 삽입하지 않습니다.

## 글쓰기 프롬프트 설정

1. **내 말투 → 카테고리별 프롬프트**에서 설정할 분류를 고릅니다. **카테고리 없음**만 보이면 데스크톱 앱에서 **카테고리 불러오기**를 누릅니다.
2. **AI 뉴스 / 인사이트 / 프로젝트 회고 / 트러블슈팅 / 개발 개념·사용법** 예시를 가져오거나 지침을 직접 적습니다. 말투, 글 순서, 분량, 피할 표현 등을 최대 10,000자로 지정할 수 있습니다.
3. **카테고리 지침 저장**을 누릅니다. 분류를 바꾸며 편집 중인 내용은 이 창 안에서 유지되지만, 카테고리마다 저장해야 앱을 다시 열어도 남습니다.
4. 작업실에서 초안을 만들기 전에 카테고리를 선택합니다. **적용할 지침**에서 선택한 분류의 지침을 확인하고 초안을 생성합니다. 아직 사진을 넣지 않았거나 초안이 없어도 카테고리 선택을 보관할 수 있습니다.

- 기존 글쓰기 지침은 아래의 **기본 블로그용 프롬프트**에 그대로 남습니다. 카테고리별 지침을 저장하거나 예시를 가져와도 기본 프롬프트는 바뀌지 않습니다.
- 별도 지침이 없는 분류는 기존 기본 프롬프트를 사용합니다. **카테고리 없음**도 별도 지침을 설정할 수 있습니다. **기본 블로그용 사용 → 카테고리 지침 저장**으로 해당 분류의 별도 지침을 해제할 수 있습니다.
- 작업실과 동일하게 하위 분류가 있는 상위 항목은 생략합니다. 같은 이름이어도 블로그·번호·전체 경로가 다르면 다른 지침으로 취급합니다. 분류 이름을 바꾸었다면 목록을 갱신하고 새 분류에서 지침을 확인하세요.
- 말투·구성은 글별 메모의 선호, 카테고리별 지침, 기본 블로그 지침 순서로 적용합니다. 확인된 사실만 쓰기, 민감정보 보호와 본문 블록 형식은 공통 규칙으로 유지합니다.
- 지침 변경은 다음 생성부터 반영합니다. 이미 만든 글을 바꾸려면 초안을 다시 생성해야 합니다. 생성 도중 설정을 고쳐도 진행 중인 글은 시작할 때 정한 지침을 사용합니다.
- 실제 사용한 지침은 초안 폴더의 `writing-context.json`에 보관합니다. 개인 지침인 `style/category-prompts.json`은 Git과 배포 EXE에 포함하지 않습니다.

## 기본 블로그용 프롬프트 · 내 말투 설정

- 사이드바 상단 버튼으로 메뉴를 접거나 펼칩니다. 접은 상태에서도 아이콘으로 메뉴를 열 수 있습니다.
- **내 말투 → 기본 블로그용 프롬프트**에서 기존 지침을 직접 수정한 뒤 **말투 저장**을 누릅니다. 기존 초안은 유지하며 다음 생성부터 새 지침을 적용합니다.
- 공개 블로그 또는 글 주소를 최대 3개 입력하고 **블로그 말투 분석하기**를 누릅니다. 각 블로그의 실제 본문을 최대 3개 읽으며, 티스토리·네이버와 공개 RSS/본문을 제공하는 블로그를 처리합니다. 로그인이 필요하거나 본문을 추출할 수 없는 곳은 실패 안내를 표시합니다.
- 분석한 말투와 참고 글을 확인하고 **이 결과로 지침 바꾸기**를 누른 뒤 원하는 대로 다듬어 저장합니다. 가져오기 전으로 되돌릴 수 있으며, 분석만으로 기존 지침이 바뀌지는 않습니다.
- 공개 본문 분석은 선택한 Codex 또는 Claude Code 계정 사용량을 사용합니다. 참고 글의 실제 경험이나 문장을 복제하지 않고 문체 특성을 일반화합니다. 로컬 말투 설정과 이전 지침 이력은 Git에서 제외합니다.

## 발행 상태

티스토리 [대표 이미지 안내](https://notice.tistory.com/2480)에 따라 첫 번째 사진을 대표 이미지로 사용하는 기본 동작을 이용합니다. 명시적으로 고른 표지를 가장 먼저 업로드하고 최종 본문 맨 위에도 배치합니다. 발행 후 공개 페이지의 `og:image`가 선택한 사진과 일치해야 표지 확인을 완료합니다. 표지 설정은 앱의 편집·업로드·재생성·발행 사본 테스트로 확인했으며, 실제 계정의 대표 이미지 설정 화면은 Windows 브라우저 주소 확인이 중단되어 이번 버전에서 추가 검증하지 못했습니다.

- **초안 보관**은 이 PC에 저장합니다. **티스토리에 발행**은 블로그에 공개 게시합니다.
- 버튼을 누른 초안과 사용하는 사진을 별도 보관하여 전송 중 내용이 바뀌지 않게 합니다. 진행 중 해당 초안 편집과 추가 발행을 막습니다.
- 로그인 만료 시 티스토리 창에서 로그인하면 이어집니다. 5분 내 로그인이 확인되지 않으면 중단하며 다시 시도할 수 있습니다.
- 편집기에 복구된 내용이 있거나 업로드·본문 확인이 실패하면 발행 전에 멈춥니다. 열린 티스토리 창에서 안내를 확인합니다.
- 최종 발행 요청 이후 결과가 불확실하면 **글 관리에서 확인** 링크를 표시하고 재전송을 막습니다. 공개 게시된 글을 자동으로 다시 만들지 않습니다.
- 이미 발행한 로컬 초안을 수정해 보관할 수는 있지만, 이 버튼으로 기존 게시글을 수정하거나 새 글로 재발행하지 않습니다. 기존 글 수정은 티스토리 관리에서 진행합니다.

티스토리 [Open API 종료 안내](https://notice.tistory.com/2664)에 따라 실제 웹 편집기와 사진 첨부 화면을 사용합니다. 티스토리가 편집 화면을 바꾸거나 추가 인증을 요구하면 연결 수정 또는 사용자 입력이 필요할 수 있습니다.

## AI와 자료 보관

- **도움말 · AI 연결**에서 Codex 또는 Claude Code를 선택합니다. 데스크톱 상단 메뉴 **도움말 → AI 선택 / 연결 방법**도 같은 화면을 엽니다.
- 초안 생성과 블로그 말투 분석에 선택한 CLI가 적용됩니다. 생성·분석 중에는 AI를 변경할 수 없습니다. 한 제공사에서 실패했다고 다른 제공사로 자동 전환하지 않습니다.
- Codex는 사용자 설정을 제외한 CLI 기본 모델, Claude Code는 사용자 확장 기능을 제외한 safe mode로 실행합니다. 앱에서 모델을 별도로 지정하지 않으며 다른 AI 대화에서 고른 모델과 같다고 보장하지 않습니다. 두 CLI 모두 최신 버전을 사용하세요.
- 사진·메모·말투 지침과 분석할 공개 본문은 선택한 제공사(OpenAI / Anthropic)에 전송됩니다. 인터넷 연결과 사용 가능한 계정이 필요하며, 계정의 요금·사용량 정책이 적용됩니다. 앱에서 비밀번호나 API 키를 입력받거나 복사하지 않습니다.
- 선택값은 자료 폴더의 `ai.settings.json`에 저장됩니다. Git과 EXE에 포함하지 않습니다. 기존 사용자는 Codex가 기본 선택입니다.
- 자료 위치는 `%APPDATA%/H.Dev Studio/workspace`입니다. 메뉴 **작업실 → 자료 폴더 열기**에서 확인합니다. EXE를 교체해도 사진과 초안은 유지됩니다.
- 티스토리 로그인은 앱 실행 중에만 유지됩니다. 앱에 비밀번호를 별도 저장하거나 로그인 쿠키를 내보내지 않습니다. 새 버전을 실행할 때 다시 로그인합니다.
- 사용자의 사진·초안·계정 자료는 EXE에 포함하지 않습니다.

**티스토리 글**에서는 공개 글 검색, 카테고리 필터, 여러 `*.tistory.com` 블로그 등록, 목록 새로고침을 지원합니다. RSS와 공개 사이트맵을 사용하며 추가 글은 한 번에 500개까지 확인합니다. 비공개·임시 글은 로그인된 티스토리 관리 화면에서 확인합니다.

## AI 연결 방법

이 EXE를 사용하는 **각 PC에서** Windows용 CLI를 설치하고 본인 계정으로 로그인하세요. Codex 데스크톱 앱은 필수가 아닙니다. WSL 안에만 설치한 CLI는 Windows EXE에서 직접 찾지 않습니다.

### Codex

[Node.js 22 이상](https://nodejs.org/en/download)을 설치하고 새 PowerShell 창에서 순서대로 실행합니다. `.cmd`를 쓰면 PowerShell의 npm 스크립트 실행 정책에 영향을 받지 않습니다.

```powershell
npm.cmd install -g @openai/codex@latest
codex.cmd login
codex.cmd login status
```

브라우저에서 Codex를 사용할 수 있는 본인의 ChatGPT 계정으로 로그인하세요. [OpenAI 공식 CLI 안내](https://developers.openai.com/codex/cli/)를 참고하세요. 다른 설치 방식으로 설치했다면 `codex login`과 `codex login status`를 사용합니다.

### Claude Code

PowerShell에서 설치합니다.

```powershell
winget install Anthropic.ClaudeCode
```

설치 후 **새 터미널**을 열고 실행합니다.

```powershell
claude auth login
claude auth status
```

Claude Code를 사용할 수 있는 본인의 Claude 계정으로 로그인하세요. WinGet을 사용할 수 없다면 [Anthropic 공식 설치 안내](https://code.claude.com/docs/en/setup)의 Windows 설치 방법을 따르세요. 업데이트는 `winget upgrade Anthropic.ClaudeCode`로 실행합니다. Claude로 분석할 사진은 한 장당 5MB 이하로 준비하세요. 사진과 메모를 합친 전송 데이터는 CLI의 10MB 입력 한도를 적용하며, 초과하면 사진 수·크기를 줄이거나 Codex를 선택하라는 안내를 표시합니다.

### 앱에서 확인

H.Dev Studio를 완전히 종료하고 다시 실행한 뒤 **도움말 · AI 연결**에서 설치한 AI를 선택하고 **연결 다시 확인**을 누릅니다. 설치 없음, 로그인 필요, 연결됨 상태를 구분해 표시합니다. 연결 확인 자체는 글을 생성하지 않으며 사용량 여유까지 보장하지 않습니다. 사용량 초과나 네트워크 오류가 나면 안내에 따라 확인 후 재시도하세요.

개발 환경에서 실행 파일이 표준 경로에 없다면 `TISTORY_CODEX_BIN` 또는 `TISTORY_CLAUDE_BIN`에 해당 실행 파일의 절대 경로를 지정한 뒤 앱을 시작할 수 있습니다. `.exe` 또는 Node 진입점 `.js`/`.mjs`를 지정하며 `.cmd`/`.ps1` 래퍼는 사용하지 않습니다.

## 개발과 빌드

Node.js 22 이상:

```powershell
npm ci
npm run setup
npm test
npm run test:desktop
npm run desktop
npm run build:exe
```

`npm start` 또는 `Start-App.ps1`은 [웹 개발 화면](http://127.0.0.1:4173/)을 엽니다. `npm run desktop`은 EXE 빌드 없이 **H.Dev Studio · 개발 모드** 창을 엽니다. 개발 모드의 기본 자료 위치는 `%APPDATA%/H.Dev Studio Dev/workspace`이며 배포 앱과 분리합니다. 직접 발행은 Electron 앱에서 지원합니다. `HDEV_DATA_DIR`로 다른 자료 폴더를 지정할 수 있지만 같은 자료를 두 앱에서 동시에 편집하지 마세요.

초기 설정, 버전 올리기와 배포 파일 관리는 [버전·배포 관리](RELEASING.md)를 참고하세요. EXE는 배포할 때 만들고 로컬에는 최신 버전 하나만 보관합니다. 과거 버전의 소스는 Git 태그에서 확인합니다.

## 검증 범위

- `npm test`: 파일 보관, 초안, API, 공개 글 목록, 자료 보존, 발행 스냅샷·중복 방지·실패 복구·공개 결과 판정 테스트. 로컬 삭제는 제외한 사진·이전 초안·편집 이력까지 실제 제거하고 다른 글을 보존하는지, 경로 이탈과 작업 중 삭제를 차단하는지 확인합니다.
- `npm run test:desktop`: 외부 접속 없는 편집기 테스트 화면에서 실제 Electron 파일 선택 창, 사진 2장 첨부, 본문 순서, 태그, 공개 설정, 한 번의 제출, 공개 내용 확인을 검증합니다.
- `npx electron validation/electron-style.mjs`: 별도 테스트 자료로 사이드바, 화면 크기 대응, 말투 편집·저장·분석·실패 복구를 확인하고 `.runtime/style-qa`에 화면을 보관합니다.
- `npm run test:writing`: 모의 AI와 별도 자료로 생성 전 카테고리 선택, 분류별 지침 저장·적용, 기본 프롬프트 보존, 다른 창과의 충돌 복구, 모바일 배치를 확인합니다. 실제 AI 글쓰기 품질이나 공개 발행 성공을 검증하는 테스트는 아닙니다.
- 표지 검증: 기존 사진 선택과 별도 업로드, 초안 재열기·재생성 후 선택 유지, 선택 해제, 잘못된 파일·경로 거부, 발행 사본에 표지 포함, 맨 위 배치와 중복 방지, 공개 대표 이미지 일치 여부를 확인합니다. 이 테스트는 실제 블로그에 글을 만들지 않습니다.
- 티스토리에 로그인된 관리 화면과 실제 편집기의 입력란·첨부 메뉴·공개 발행 설정을 확인했습니다. 자동화 테스트가 실제 블로그의 게시 성공을 뜻하지는 않습니다. 임의의 테스트 글은 공개 발행하지 않았습니다.
- 개발 실행에서만 `HDEV_PUBLISH_DRY_RUN=1`을 설정하면 최종 공개 발행 직전에 멈춥니다. `publish-dry-run.json`은 입력 검증 결과이며 발행 영수증이 아닙니다. 배포 EXE는 이 개발 옵션을 사용하지 않습니다.

## 파일 구조

- `desktop/`: Electron 앱과 티스토리 발행 동작
- `scripts/server.mjs`: 로컬 API, `scripts/generate.mjs`: Codex 초안 생성
- `scripts/publication.mjs`: 전송 스냅샷과 발행 상태·확인
- `scripts/tistory.mjs`: 공개 글 목록, `scripts/blog.mjs`: 자료와 미리보기
- `web/`: 사진·편집·미리보기 화면
- `inbox/<글-ID>/`: 원본 사진, 메모, `publication.json` 발행 상태
- `drafts/<글-ID>/<입력해시>/`: 초안, 미리보기, 편집 이력
- 초안 아래 `publication/<시도-ID>/`: 전송한 사진·초안, 성공 시 `published-receipt.json`
- `style/profile.md`: 기존 블로그를 참고한 말투 지침

사진을 목록에서 제외해도 디스크 원본은 유지합니다. 생성 실패 시 이전 초안을 보존합니다. 폴더 감시·예약 실행·아이폰 배포는 아직 설정하지 않았습니다.

보관함에 표시하는 용량은 해당 글 폴더의 파일 크기 합계입니다. **글 삭제**는 휴지통을 거치지 않으므로 복구할 수 없습니다.
