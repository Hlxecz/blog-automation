# H.Dev Studio 사용 안내

개발 캡처와 메모로 내 말투의 초안을 만들고, 편집·미리보기 후 **티스토리에 발행** 버튼으로 공개 게시하는 Windows 앱입니다.

## 사용법

1. `HDev-Studio-<버전>-win-x64.exe`를 실행합니다. 설치가 필요 없는 Windows 64비트 앱입니다. 직접 빌드한 파일은 `dist/<버전>/`에서 찾을 수 있습니다.
2. **로그인 / 글 관리**에서 티스토리에 로그인합니다.
3. 사진을 업로드하고 주제·메모를 적습니다. PNG/JPEG/WebP, 한 장 10MB, 한 글 20장까지 지원합니다.
4. **내 말투로 초안 만들기**를 누릅니다. 제목, 태그, 문단, 코드, 사진 설명과 순서를 편집하고 미리보기로 검토합니다.
   - 초안 위 **표지 · 대표 이미지**에서 **사진에서 선택** 또는 **표지 업로드**를 누릅니다. 표지는 즉시 로컬 저장하며, 새로 업로드한 표지는 글의 재료 목록과 별도로 보관합니다.
   - 선택한 사진을 본문 맨 위로 배치합니다. 이미 본문에 있던 사진은 설명을 유지하며 앞쪽으로 옮기므로 중복 추가하지 않습니다. **선택 해제**를 누르면 원래 본문 순서와 첫 사진을 사용하는 자동 표지로 돌아갑니다.
5. **티스토리에 발행**을 누르면 현재 편집을 먼저 보관하고, 사진 업로드 → 본문·태그 입력 → 공개 발행을 진행합니다. 추가 발행 확인 팝업은 없습니다.
6. 공개된 제목·본문·사진을 확인하면 앱에 **발행 완료**와 글 링크가 표시됩니다.
7. 공간을 비우려면 **보관한 글 → 해당 글의 삭제** 또는 작업실 상단 **삭제**를 누릅니다. 글 제목과 정리할 용량을 확인한 뒤 **이 PC에서 영구 삭제**를 누르면 해당 글의 사진 원본·메모·모든 입력 버전의 초안·편집 이력·발행용 사본을 지웁니다. 티스토리 게시글은 유지하며, 작성·발행 중인 글은 완료 후 삭제할 수 있습니다.

발행 대상은 자료 폴더의 `tistory.config.json`에 있는 `blogUrl`입니다. 개발 실행에서는 프로젝트의 설정을 사용합니다. 여러 블로그를 글 목록에 추가해도 발행 대상은 자동으로 바뀌지 않습니다. 카테고리는 티스토리 새 글 편집기의 기본값을 사용합니다. 기존 글 수정은 **로그인 / 글 관리**의 티스토리 화면에서 합니다.

## 발행 상태

티스토리 [대표 이미지 안내](https://notice.tistory.com/2480)에 따라 첫 번째 사진을 대표 이미지로 사용하는 기본 동작을 이용합니다. 명시적으로 고른 표지를 가장 먼저 업로드하고 최종 본문 맨 위에도 배치합니다. 발행 후 공개 페이지의 `og:image`가 선택한 사진과 일치해야 표지 확인을 완료합니다. 표지 설정은 앱의 편집·업로드·재생성·발행 사본 테스트로 확인했으며, 실제 계정의 대표 이미지 설정 화면은 Windows 브라우저 주소 확인이 중단되어 이번 버전에서 추가 검증하지 못했습니다.

- **초안 보관**은 이 PC에 저장합니다. **티스토리에 발행**은 블로그에 공개 게시합니다.
- 버튼을 누른 초안과 사용하는 사진을 별도 보관하여 전송 중 내용이 바뀌지 않게 합니다. 진행 중 해당 초안 편집과 추가 발행을 막습니다.
- 로그인 만료 시 티스토리 창에서 로그인하면 이어집니다. 5분 내 로그인이 확인되지 않으면 중단하며 다시 시도할 수 있습니다.
- 편집기에 복구된 내용이 있거나 업로드·본문 확인이 실패하면 발행 전에 멈춥니다. 열린 티스토리 창에서 안내를 확인합니다.
- 최종 발행 요청 이후 결과가 불확실하면 **글 관리에서 확인** 링크를 표시하고 재전송을 막습니다. 공개 게시된 글을 자동으로 다시 만들지 않습니다.
- 이미 발행한 로컬 초안을 수정해 보관할 수는 있지만, 이 버튼으로 기존 게시글을 수정하거나 새 글로 재발행하지 않습니다. 기존 글 수정은 티스토리 관리에서 진행합니다.

티스토리 [Open API 종료 안내](https://notice.tistory.com/2664)에 따라 실제 웹 편집기와 사진 첨부 화면을 사용합니다. 티스토리가 편집 화면을 바꾸거나 추가 인증을 요구하면 연결 수정 또는 사용자 입력이 필요할 수 있습니다.

## AI와 자료 보관

- AI는 이 PC에 설치하고 로그인한 **OpenAI Codex CLI**를 사용합니다. 별도 API 키를 연결하지 않았습니다.
- `--ignore-user-config`로 실행해 CLI 기본 모델을 사용합니다. Codex 대화에서 고른 모델과 같다고 보장하지 않습니다.
- 사진·메모·말투 지침을 OpenAI에 전송하는 온라인 생성이며 Codex 계정 사용량을 사용합니다.
- 다른 PC에서는 Codex CLI 설치와 로그인이 필요합니다. `TISTORY_CODEX_BIN`으로 실행 파일 위치를 지정할 수 있습니다.
- 자료 위치는 `%APPDATA%/H.Dev Studio/workspace`입니다. 메뉴 **작업실 → 자료 폴더 열기**에서 확인합니다. EXE를 교체해도 사진과 초안은 유지됩니다.
- 티스토리 로그인은 앱 실행 중에만 유지됩니다. 앱에 비밀번호를 별도 저장하거나 로그인 쿠키를 내보내지 않습니다. 새 버전을 실행할 때 다시 로그인합니다.
- 사용자의 사진·초안·계정 자료는 EXE에 포함하지 않습니다.

**티스토리 글**에서는 공개 글 검색, 카테고리 필터, 여러 `*.tistory.com` 블로그 등록, 목록 새로고침을 지원합니다. RSS와 공개 사이트맵을 사용하며 추가 글은 한 번에 500개까지 확인합니다. 비공개·임시 글은 로그인된 티스토리 관리 화면에서 확인합니다.

## 개발과 빌드

Node.js 22 이상:

```powershell
npm ci
npm run setup
npm test
npm run test:desktop
npm run desktop
npm run build:exe
```

`npm start` 또는 `Start-App.ps1`은 [웹 개발 화면](http://127.0.0.1:4173/)을 엽니다. 직접 발행은 Electron 앱에서 지원합니다. `HDEV_DATA_DIR`로 다른 자료 폴더를 지정할 수 있지만 같은 자료를 두 앱에서 동시에 편집하지 마세요.

초기 설정, 버전 올리기와 배포 파일 관리는 [버전·배포 관리](RELEASING.md)를 참고하세요. EXE는 배포할 때 만들고 로컬에는 최신 버전 하나만 보관합니다. 과거 버전의 소스는 Git 태그에서 확인합니다.

## 검증 범위

- `npm test`: 파일 보관, 초안, API, 공개 글 목록, 자료 보존, 발행 스냅샷·중복 방지·실패 복구·공개 결과 판정 테스트. 로컬 삭제는 제외한 사진·이전 초안·편집 이력까지 실제 제거하고 다른 글을 보존하는지, 경로 이탈과 작업 중 삭제를 차단하는지 확인합니다.
- `npm run test:desktop`: 외부 접속 없는 편집기 테스트 화면에서 실제 Electron 파일 선택 창, 사진 2장 첨부, 본문 순서, 태그, 공개 설정, 한 번의 제출, 공개 내용 확인을 검증합니다.
- 표지 검증: 기존 사진 선택과 별도 업로드, 초안 재열기·재생성 후 선택 유지, 선택 해제, 잘못된 파일·경로 거부, 발행 사본에 표지 포함, 맨 위 배치와 중복 방지, 공개 대표 이미지 일치 여부를 확인합니다. 이 테스트는 실제 블로그에 글을 만들지 않습니다.
- 티스토리에 로그인된 관리 화면과 실제 편집기의 입력란·첨부 메뉴·공개 발행 설정을 확인했습니다. 자동화 테스트가 실제 블로그의 게시 성공을 뜻하지는 않습니다. 임의의 테스트 글은 공개 발행하지 않았습니다.
- 개발 실행에서만 `HDEV_PUBLISH_DRY_RUN=1`을 설정하면 최종 공개 발행 직전에 멈춥니다. `publish-dry-run.json`은 입력 검증 결과이며 발행 영수증이 아닙니다. 배포 EXE는 이 개발 옵션을 사용하지 않습니다.

## 파일 구조

- `desktop/`: Electron 앱과 티스토리 발행 동작
- `scripts/server.mjs`: 로컬 API, `scripts/generate.mjs`: Codex 초안 생성
- `scripts/publication.mjs`: 전송 스냅샷과 발행 상태·확인
- `scripts/tistory.mjs`: 공개 글 목록, `scripts/blog.mjs`: 자료와 미리보기
- `web/`: 사진·편집·미리보기 화면
- `inbox/<글-ID>/`: 원본 사진, 메모, `publication.json` 발행 상태
- `drafts/<글-ID>/<입력해시>/`: 초안, 미리보기, 편집 이력
- 초안 아래 `publication/<시도-ID>/`: 전송한 사진·초안, 성공 시 `published-receipt.json`
- `style/profile.md`: 기존 블로그를 참고한 말투 지침

사진을 목록에서 제외해도 디스크 원본은 유지합니다. 생성 실패 시 이전 초안을 보존합니다. 폴더 감시·예약 실행·아이폰 배포는 아직 설정하지 않았습니다.

보관함에 표시하는 용량은 해당 글 폴더의 파일 크기 합계입니다. **글 삭제**는 휴지통을 거치지 않으므로 복구할 수 없습니다.
