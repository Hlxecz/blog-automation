# 기능별 구현 규칙

이 문서는 AGENTS.md에서 분리한 세부 계약과 실제 화면 관찰 기록입니다. 해당 기능을 변경할 때 관련 항목을 확인하고, 기존 사용자 자료와 저장 형식을 보존합니다.

커밋 메시지는 2026-09-22 사용자 요청에 따라 `타입: 한국어 설명`으로 작성합니다. 타입은 `feat`, `fix`, `docs`, `style`, `refactor`, `test`, `chore` 중 변경 목적에 맞게 고르고, 설명과 본문은 한국어로 씁니다. 한 커밋에는 하나의 목적을 담고 독립적인 작업은 나눕니다. 자세한 기준과 예시는 `docs/RELEASING.md`의 커밋 메시지 규칙을 따릅니다.

## 카테고리 프롬프트 예시

## 글 다듬기

2026-09-22 사용자는 칸별·선택·전체 글 다듬기를 요청했습니다. `scripts/refine.mjs`는 기존 CLI 연결을 사용하고 `scripts/server.mjs`가 실행 시점의 초안·기본 말투·카테고리 지침을 고정합니다. 결과는 선택한 텍스트 필드에만 적용하며 칸 종류·목록 및 표 구조·이미지 파일·코드·제목·태그·카테고리·표지·GitHub 카드를 유지합니다. 이전 초안은 `history/`와 `refinement-undo.json`에 보관하고 이후 편집이 없을 때만 되돌립니다. `npm run test:refine`은 오프라인 AI 결과로 실제 편집 화면을 확인합니다. 직접 작성은 사진 없이 허용하되 사진 기반 초안 생성과 기본 CLI ready 명령의 사진 요구는 유지합니다.

## 기본 말투 프로필 갱신

2026-09-22 사용자는 기존 H.Dev Log 말투 프로필 6,408자 전체를 새 배포본에도 기본으로 포함하라고 요청했습니다. 승인된 사본은 `config/style.example.md`로 공유하며 로컬 원본은 계속 Git에서 제외합니다. `desktop/data.mjs`는 구버전 기본 템플릿과 내용 해시가 일치할 때만 원본을 `style/history/`에 백업한 후 교체합니다. 사용자 수정본·별도 프로필 경로·카테고리 지침·사진·초안·계정 설정은 보존합니다. 프로필 속 참고 블로그 주소를 로그인·발행 대상 설정으로 사용하지 않습니다.

## 카테고리별 글쓰기 지침

기존 말투 프로필은 **기본 블로그용 프롬프트**로 유지합니다. 카테고리별 지침은 `scripts/writing-prompts.mjs`가 로컬 `style/category-prompts.json`에 별도로 보관하며 Git과 EXE에서 제외합니다. AI 뉴스·인사이트·프로젝트 회고·트러블슈팅·개발 개념 및 사용법 예시는 사용자가 가져와 저장한 경우에만 적용합니다. 블로그·카테고리 ID·전체 경로가 일치하는 지침만 사용하고, 별도 지침이 없으면 기존 기본 프롬프트를 그대로 사용합니다. 초안이 없을 때 선택한 카테고리는 글의 `app.json`에 보관하며, 초안 생성 이후는 `draft.category`가 기준입니다. 생성 시작 시 공통 지침과 카테고리 지침을 고정하고 성공한 초안 옆 `writing-context.json`에 기록합니다. 카테고리 지침은 문체·구성에 우선하며 사실 확인·민감정보 보호·JSON 형식 규칙은 유지합니다. `npm run test:writing`은 모의 AI와 임시 자료로 이 연결과 기본 지침 보존을 검증합니다.

## 발행 카테고리

발행 카테고리는 선택적인 `draft.category`의 `{blogUrl,id,path}`로 보관합니다. `path`는 상위·하위 이름 배열이며 AI 재생성 시 사용자의 선택을 유지합니다. `scripts/categories.mjs`는 블로그별 목록을 로컬 `library/categories.json`에 보관하고, 데스크톱의 `createTistoryCategoryReader`는 2026-09-18에 관찰한 `/manage/posts`의 보기 → 카테고리별 보기 목록을 읽습니다. `.opt_blog > .btn_opt`, `.scroll_opt > ul.list_opt`, 계층별 `a.lab_btn`의 `category` 쿼리와 `.inner_lab`을 사용합니다. 카테고리 조회에서는 새 글 편집기를 열지 않습니다. 2026-09-16 실제 화면에서 `category-btn`, `category-list`, `category-item-<ID>`, `category-id`, `aria-label`을 확인했습니다. 옵션의 `aria-selected`는 키보드 초점이므로 선택 확인에 사용하지 않습니다. 번호와 전체 경로를 대조해 클릭한 뒤 버튼 표시를 확인하며, 삭제·변경된 분류에 임의로 대체 발행하지 않습니다. 공개 글의 `a.category` 경로까지 맞아야 카테고리 검증을 기록합니다. 2026-09-18 요청에 따라 앱 기본 선택은 **카테고리 없음**(ID `0`)으로 통합하며, 생성·수동 작성 및 앱의 발행 버튼에서 명시적으로 보관합니다. 작업실과 프롬프트 설정의 선택 목록은 `web/draft-model.js`의 `selectableCategories`로 하위 분류가 있는 상위 항목을 생략하고, 같은 이름이 겹칠 때만 상위 이름을 붙입니다. 캐시와 발행 검증에는 전체 경로를 유지하고 기존 상위 분류 선택·저장된 지침은 삭제하지 않습니다. 필드가 없는 예전 초안을 저수준 발행 API로 보내는 경우의 기존 편집기 기본값 동작은 유지합니다.

## 설치·버전·자료 정리

새로 받은 소스는 `npm ci`와 `npm run setup`으로 준비한다. 개인 설정과 말투 원문은 Git에서 제외하며 공유용 기본값은 `config/`에서 관리한다. 기존 설정을 덮어쓰지 않는다. 버전은 `package.json`과 잠금 파일에 맞추고 변경 내용은 `CHANGELOG.md`에 기록한다. 배포 절차는 `docs/RELEASING.md`를 따른다. 개발 확인은 `npm run desktop`을 사용하고, EXE는 배포 시 빌드한다. 사용자는 2026-09-15에 `Hlxecz/blog-automation` 저장소 생성, 버전별 순차 푸시와 불필요한 빌드 파일 삭제를 요청했다. 로컬 EXE는 최신 버전 하나만 보관하며 과거 소스는 Git 커밋·태그로 관리한다. 정리 전 백업된 소스와 최신 EXE를 확인하고, 사진·초안·설정은 삭제하지 않는다. `v0.3.0`~`v0.3.4`는 배포본 소스에서 복원했으며 범위는 `docs/HISTORY.md`에 기록했다.

## 목차와 팁·주의 상자

사용자는 2026-09-16에 모든 글의 본문 맨 위에 목차를 먼저 표시하고 팁·주의를 CSS 상자로 꾸미도록 요청했습니다. `web/article-renderer.js`를 앱·로컬 미리보기·발행 HTML에서 함께 사용합니다. 목차는 heading으로 자동 생성하며 본문·표지보다 앞에 표시합니다. 기존 스킨이 목차를 만드는 블로그는 로컬 설정 `tocMode: "skin"`을 사용해 발행 본문에 목차를 중복 삽입하지 않습니다. 기본값은 본문 목차입니다. 💡·⚠️ 문단의 첫 줄은 상자 제목, 나머지는 설명으로 표시합니다. 초안 원문은 변경하지 않으며 AI가 HTML/CSS를 직접 작성하게 하지 않습니다.

## 로컬 글 삭제

로컬 글 삭제는 사용자가 앱의 삭제 확인 버튼을 누른 글 ID에만 적용합니다. `inbox/<ID>`와 `drafts/<ID>`의 전체 입력 버전·사진·이력·발행용 사본을 함께 제거하며 티스토리 게시글은 건드리지 않습니다. `scripts/storage.mjs`에서 작업 공간 내 실제 경로와 일반 파일 트리를 확인한 뒤 삭제합니다. 생성·발행 중에는 삭제할 수 없습니다. 사용자 자료를 삭제 기능의 테스트 대상으로 사용하지 않습니다.

## 실행 환경과 코드 구조

Node.js 22 앱이며 Electron으로 Windows EXE와 macOS arm64/x64 DMG·ZIP을 빌드한다. Mac 빌드는 `npm run build:mac`(현재 CPU) 또는 `npm run build:mac:all`(두 CPU)을 사용하며 맥 기능 검사는 `npm run test:lifecycle`을 포함한다. `desktop/main.mjs`는 독립 앱 창과 격리된 티스토리 창, `desktop/publish.mjs`는 실제 편집기 연결, `scripts/publication.mjs`는 발행 상태·스냅샷·공개 내용 검증, `scripts/tistory.mjs`는 공개 RSS/사이트맵 목록, `scripts/server.mjs`는 로컬 HTTP API, `scripts/generate.mjs`는 Codex CLI 호출, `web/`은 화면, `scripts/blog.mjs`는 기존 파일 처리 기능이다. 앱의 `order.json`은 활성 이미지와 사용자 지정 순서를 나타내며 제외된 사진의 원본 파일은 지우지 않는다.

## 공개 목록·인증·자료 보관

공개 글 목록과 계정 로그인 상태를 혼동하지 않는다. 티스토리 Open API는 종료되었으므로 공식 편집 화면을 사용한다. 앱은 로그인 창을 제공하고 사용자가 직접 기존 글 수정/발행을 할 수 있다. 이는 에이전트가 기존 글을 임의로 수정·발행해도 된다는 뜻이 아니다. 인증된 화면 확인 전 편집이나 저장 성공을 주장하지 않는다. 데스크톱 자료는 Windows의 `%APPDATA%/H.Dev Studio/workspace`, macOS의 `~/Library/Application Support/H.Dev Studio/workspace`에 저장하고, EXE에 사용자 사진/초안/로그인 자료를 포함하지 않는다.

## 자동 검증과 저장 방지 모드

준비 상태, 입력 고정, 중복 재실행, 미리보기, 업로드·초안 저장·생성 실패 복구·발행 상태는 `npm test`로 확인한다. `npm run test:desktop`은 외부 접속 없는 편집기 테스트 화면에서 Electron 파일 첨부와 본문·태그·공개 설정을 확인한다. 이 테스트는 실제 티스토리 게시 성공을 증명하지 않는다. `desktop/publish.mjs`의 컨트롤은 로그인된 실제 편집기에서 관찰한 ID를 사용하며 화면이 달라지면 중단한다. `HDEV_PUBLISH_DRY_RUN=1` 개발 실행은 최종 발행 직전에 멈춘다. 배포 EXE에서는 이 개발 옵션을 사용하지 않는다.

## 운영 블로그 연결

새 PC에서 `your-blog.tistory.com`은 미설정 상태입니다. 2026-09-18 사용자 요청에 따라 데스크톱의 **티스토리 로그인**은 `desktop/account.mjs`가 `/member/blog`를 열어 로그인한 계정의 운영 블로그를 읽습니다. 실제 계정 화면에서 확인한 `ul.ac-ul-blog > li.ac-li-blog`, `a.ac-item-thumb` 관리 주소와 `.ac-item-desc strong` 이름만 사용하며 추천·외부 블로그를 소유 블로그로 취급하지 않습니다. 하나면 자동 연결, 여러 개면 사용자가 선택합니다. `/api/tistory/connect`의 확인 목록은 메모리에만 유지하며 주소 선택은 `/api/blog-settings`가 저장합니다. 연결 후 공개 글과 카테고리를 불러오고 발행 대상도 갱신합니다. 계정 목록이 바뀌어도 기존 초안·사진·기본 말투는 수정하지 않습니다. 웹 모드는 주소 직접 입력을 유지합니다. 예시 주소 이동·카테고리 조회·발행은 차단하고 진행 중인 작업에서는 계정을 바꾸지 않습니다. 로그인 리다이렉트의 ERR_ABORTED는 네트워크 장애로 안내하지 않습니다. `npm run test:setup`은 웹 모드 주소 설정을, `npm run test:account`는 오프라인 계정 화면으로 로그인·단일/복수 블로그·계정 변경·글/카테고리 연결·취소/실패·자료 보존을 확인합니다.

## 기존 글 가져오기

기존 공개 글 수정은 공개 글 목록의 **작업실에서 수정**을 사용합니다. 가져온 글의 대상 블로그·공개 URL·글 번호와 원문 스냅샷은 `inbox/<ID>/existing-post.json`에 서버가 기록하며 초안의 값으로 대상을 바꾸지 않습니다. 같은 URL은 기존 로컬 작업을 다시 열어 사용자 편집을 덮어쓰지 않습니다. 일반 문단·소제목·목록·코드는 손실이 없을 때만 기존 블록으로 바꾸고, 링크·강조·표 스타일·티스토리 사진 메타데이터가 있는 부분은 정제된 원문 형식 틀과 편집 가능한 문장으로 보존합니다. 외부 스크립트·이벤트·위험한 URL은 실행하지 않으며 원문 사진 미리보기는 허용한 호스트와 크기로 제한합니다.

## 기존 글 수정 반영

**기존 글에 수정 반영** 버튼은 명시적인 수정 의사이며 추가 확인 팝업을 띄우지 않습니다. 새 글 작성 주소를 열지 않고 원래 글에서 확인한 수정 링크와 같은 글의 편집기 주소만 사용합니다. 공개 URL·공개 상태·기존 발행 시각을 유지하고 새 로컬 사진만 업로드합니다. 편집기를 채우기 전과 최종 저장 직전에 공개 원문 digest를 확인하며, 서명된 이미지 URL의 만료 매개변수만 바뀐 경우는 충돌로 보지 않습니다. 다른 내용이 바뀌면 로컬 수정본을 유지한 채 `stale`로 중단합니다. 저장 클릭 전 실패는 재시도할 수 있고 클릭 후 결과가 불확실하면 `uncertain`으로 기록해 자동 재시도하지 않습니다. 사용자가 **원문 다시 불러오기**를 누르면 로컬 수정본을 `conflict-backups/`에 보관하고 최신 원문과 합친 뒤 다시 검토합니다. 실제 글 수정 검증은 모의 편집기만 사용하며 테스트 글을 공개하거나 실제 기존 글을 바꾸지 않습니다.
