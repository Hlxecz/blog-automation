## 여러 글에서 찾은 공통점

다음은 위 글들을 비교해 도출한 판단입니다. 모든 글이 동일한 형식을 따른다는 뜻은 아닙니다.

1. **독자가 읽을 이유를 먼저 제시합니다.** 제품 변화, 실무의 불편, 재현되는 오류, 개념이 필요한 상황처럼 구체적으로 시작합니다.
2. **설명 옆에 근거가 있습니다.** 예제·화면·관찰·조건을 해당 설명 가까이에 배치합니다.
3. **무엇을 했는지와 왜 했는지를 연결합니다.** 기능 이름이나 작업 순서만 나열하지 않습니다.
4. **읽기 단위를 작게 나눕니다.** 소제목은 실제 질문이나 요점을 보여주고, 표·목록은 비교와 절차에 사용합니다.
5. **독자의 다음 판단으로 이어집니다.** 적용 조건, 한계, 다음 시도나 상세 자료를 남깁니다.

각 예시에 목표·말투, 전개, 근거·표현, 마무리·점검을 추가했습니다. 사실·해석 구분, 가상 경험 금지, 미확인 검증을 성공으로 표현하지 않기 등은 앱의 기존 작성 원칙을 강화한 규칙입니다. 자료가 적으면 짧게 쓰고, 자료가 없는 절을 채우기 위해 내용을 만들지 않도록 했습니다.

## 앱에서 사용하기

**내 말투 → 설정할 카테고리 선택 → 시작할 때 참고할 예시 선택 → 예시 가져오기 → 지침 저장** 순서입니다. 저장한 지침은 해당 블로그·카테고리 ID·전체 경로가 일치할 때 초안 생성과 글 다듬기에 적용됩니다. 예시를 가져오면 편집 칸이 바뀌며, 저장해야 실제 적용됩니다.

- 개선 대상: `scripts/writing-prompts.mjs`의 AI 뉴스, 인사이트, 프로젝트 회고, 트러블슈팅, 개발 개념·사용법 예시 5종.
- 사용자 기본 블로그 프롬프트 6,408자는 그대로 유지합니다.
- 기존에 직접 저장한 카테고리 지침은 자동 교체하지 않습니다. 새 예시를 가져온 뒤 원하는 내용을 더하고 저장할 수 있습니다.
- 예시의 참고 글들은 글 구성 연구용입니다. 앞으로 생성할 글의 사실·경험·출처로 자동 삽입하지 않습니다.
- 글 다듬기는 선택한 칸의 표현을 개선합니다. 이 전체 글 구성 예시 때문에 선택하지 않은 칸·코드·사진을 바꾸거나 새로운 절을 추가하지 않습니다.

## 검증 범위

카테고리 저장·불러오기·기본 프롬프트 보존·생성 및 다듬기로 전달되는 연결은 모의 AI와 오프라인 화면 검사로 확인합니다. 글의 품질 향상은 지침 설계의 목표이며, 모델별 실제 생성 품질을 비교 평가한 결과는 아닙니다.
