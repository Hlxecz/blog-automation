# 소스 이력 안내

저장소: [Hlxecz/blog-automation](https://github.com/Hlxecz/blog-automation)

## 복원한 버전

프로젝트에 과거 Git 커밋이 없어, 남아 있던 Electron 배포본의 `app.asar`와 함께 배포된 분리 파일에서 앱 소스를 추출했습니다. 각 버전을 순서대로 커밋하고 태그를 붙였습니다. 커밋 날짜는 이력을 정리한 날짜이며 당시 개발 시각을 재현하지 않았습니다.

| 태그 | 주요 내용 | 앱 소스 파일 수 |
| --- | --- | ---: |
| `v0.3.0` | 검토 후 버튼 한 번으로 공개 발행 | 14 |
| `v0.3.1` | 이미지 요소와 태그 입력 수정 | 14 |
| `v0.3.2` | 자료 폴더와 공개 발행 결과 확인 보완 | 14 |
| `v0.3.3` | 로컬 글 용량 표시와 전체 자료 삭제 | 15 |
| `v0.3.4` | 표지 선택·업로드와 대표 이미지 확인 | 16 |

`0.2.0`은 소스가 남아 있지 않아 태그를 만들지 않았습니다. [변경 내역](../CHANGELOG.md)에 기능 기록만 남겼습니다.

## 포함한 것과 복원 한계

- `desktop/`, `scripts/`, `web/`의 앱 소스와 아이콘은 해당 배포본에서 추출했습니다. 텍스트 줄바꿈을 LF로 정리하고, 개인 블로그 기본 링크와 표시 이름을 공용 값으로 교체했습니다. 교체한 파일은 복원 기록의 `redactions`에 표시했습니다.
- 각 파일의 원본 해시가 배포 아카이브의 무결성 정보와 일치하는지 확인했습니다. 분리된 `desktop/publish.mjs`도 포함합니다.
- `0.3.1`의 기존 빌드 폴더에는 나중에 수정된 발행 코드가 있어, 해당 버전의 원본 EXE에서 파일을 다시 추출해 무결성을 확인했습니다.
- 패키징 과정에서 빠진 개발용 `package.json` 설정과 잠금 파일은 현재 도구 버전을 바탕으로 보완했습니다. 개인 설정 대신 공용 예제와 `npm run setup`을 추가했습니다. 당시 개발 환경 전체를 그대로 복구한 것은 아닙니다.
- 당시 테스트 소스는 배포본에 없어 과거 태그에 넣지 않았습니다. 현재 테스트와 저장소 관리 문서는 태그 이후 `main` 브랜치의 별도 커밋에 있습니다.
- 사진, 초안, 개인 말투 지침·원문, 로그인 자료, EXE와 의존성 폴더는 Git에 넣지 않았습니다.

[recovered-sources.json](recovered-sources.json)에 원본 아카이브 경로·SHA256과 버전별 파일 해시를 기록했습니다. 과거 태그에는 그 버전의 `docs/recovered-source.json`이 있습니다. 로컬 빌드 파일을 정리해도 소스와 이 검증 기록은 Git에 남습니다.

공유 이력의 작성자는 프로젝트 이름을 사용하고 이메일은 GitHub의 `noreply` 주소로 설정했습니다. 저장소 소유자의 GitHub 계정명과 저장소 주소는 표시됩니다.

## 앞으로의 버전

새 기능은 현재 `main`에서 개발하고 검사한 뒤 커밋합니다. 배포할 때 버전을 올리고 해당 소스 커밋에 새 태그를 붙입니다. 복원 태그의 커밋이나 기존 태그는 변경하지 않습니다.
