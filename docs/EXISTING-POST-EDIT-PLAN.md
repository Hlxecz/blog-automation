# 기존 글을 작업실에서 다시 편집하기

## 목표

티스토리에 이미 공개한 글을 H.Dev Studio 작업실로 불러와 수정하고, 사용자가 검토한 뒤 같은 게시글에 반영한다. 기존 글의 주소와 발행 이력을 유지한다.

## 사용 흐름

1. **내 블로그 → 기존 글 목록 → 작업실에서 수정**을 누른다.
2. 작업실에 수정용 사본을 만든다. 이미 가져온 글이면 저장한 편집 내용을 이어서 연다.
3. 작업실 상단에서 **기존 글 수정**, 원문 제목과 주소, 불러온 시각을 확인한다.
4. 제목·본문·사진·태그·카테고리를 수정하고 미리본다. **보관**은 이 PC의 사본만 저장한다.
5. **기존 글에 수정 반영**을 누르면 원문이 이후 바뀌었는지 확인하고, 원래 게시글의 편집 화면에서 저장한다.
6. 같은 주소의 공개 글을 확인한 뒤 수정 완료로 표시한다. 그 뒤에도 다시 편집할 수 있다.

## 원문과 편집 내용 보존

- 게시글의 원래 주소와 식별 정보는 서버가 보관한다. 초안에 입력한 주소로 발행 대상을 바꿀 수 없다.
- 원문 사본과 수정 이력을 로컬에 남긴다. 다시 가져오기 때문에 작업 중인 내용을 덮어쓰지 않는다.
- 굵은 글씨, 링크, 표, 코드, 사진과 설명 등은 불러올 때 유지한다.
- 기존 편집 칸에서 표현할 수 없는 형식은 보존된 원문으로 구분해 보여준다. 변환 과정에서 본문을 조용히 생략하지 않는다.
- 기존 티스토리 사진은 원래 연결을 유지하고 새로 추가한 사진만 업로드한다. 만료 시각이 포함된 공개 이미지 주소는 영구 식별자로 사용하지 않는다.
- 외부 HTML을 앱의 실행 영역에 직접 넣지 않는다. 실행 가능한 요소를 제거하고 원문 미리보기는 앱과 분리한다.

## 수정 반영 규칙

- 연결된 블로그와 원문 소유 권한을 확인한다. 다른 블로그의 글은 같은 버튼으로 수정할 수 없다.
- 수정 반영은 사용자가 버튼을 눌렀을 때만 실행한다. 중간 재확인 팝업은 추가하지 않는다.
- 새 글을 생성하지 않는다. 원래 주소·공개 상태·발행 시각을 유지한다.
- 불러온 뒤 티스토리에서 원문이 바뀌었으면 덮어쓰지 않는다. 로컬 사본을 보관한 채 원문을 확인하고 다시 가져올 수 있도록 안내한다.
- 저장 요청 전에 실패하면 수정 내용을 보관하고 재시도를 허용한다. 저장 요청 후 결과가 불확실하면 자동 재시도를 막고 원문 확인을 안내한다.
- 수정되지 않은 동일 내용의 반복 반영은 방지하며, 새로 편집한 내용은 이후 다시 반영할 수 있다.

## 검증 기준

| 확인할 상황 | 기대 결과 |
| --- | --- |
| 표·코드·링크·사진이 있는 글 불러오기 | 본문 순서와 형식이 유지되고 댓글·스킨 영역은 제외됨 |
| 이미 가져온 글을 다시 선택 | 저장한 작업실 사본이 열리고 중복 자료가 생기지 않음 |
| 편집 후 보관·재열기 | 수정 내용과 원문 연결이 유지됨 |
| 티스토리에서 원문이 바뀜 | 수정 반영 중단, 로컬 수정 내용 보존 |
| 같은 원문의 서명된 사진 주소만 갱신됨 | 실제 본문 충돌로 잘못 판단하지 않음 |
| 다른 블로그 또는 잘못된 편집 대상 | 저장 전에 거부 |
| 수정 반영 완료 | 기존 주소의 변경된 본문을 확인하고 완료 기록 저장 |
| 저장 후 통신 실패 또는 앱 종료 | 결과 불확실 표시, 자동 중복 저장 없음 |
| 기존 새 글 작성·발행 | 기존 동작 유지 |

실제 공개 글을 테스트 대상으로 수정하지 않는다. 자동 검사는 격리된 자료와 모의 티스토리 편집기로 수행하고, 실제 화면에서 확인한 범위는 별도로 기록한다.

## 구현 및 배포

- 기획·검토는 주 작업에서 진행하고, 구현은 사용자 요청에 따라 **GPT-5.6 Sol / High**로 진행한다.
- 다른 작업에서 수정 중인 파일과 사용자 자료를 보존한다.
- 작업 중 변경은 `Unreleased`에 기록한다. EXE 빌드와 버전 배포는 구현·검증 후 별도 배포 단계에서 수행한다.

## 이번 구현의 범위

- 공개 글 목록에 있는 글을 가져온다. 비공개 글과 임시글은 기존 티스토리 글 관리에서 확인한다.
- 일반 문단과 소제목은 기존 작업실 칸으로 편집한다. 복잡한 원문은 **원문 문장 편집**을 펼쳐 텍스트를 고치며, 링크 주소와 표 구조 등 원문의 형식은 유지한다. 원문 형식 칸의 AI 다듬기는 이번 범위에 포함하지 않는다.
- 가져올 수 없는 외부 콘텐츠는 표시 안내를 남긴다. 가져온 원본 HTML은 실행하지 않는 로컬 사본으로 보관한다.
- 저장 실패나 원문 변경 시 현재 글을 버리지 않는다. **원문 다시 불러오기**와 **이전 로컬 수정본 보기**로 검토를 이어간다.

## 확인한 내용

- Node 자동 검사 89개와 기존 Electron 발행·계정 연결·글 다듬기·카테고리·프롬프트·첫 실행 설정 검사를 통과했다.
- `npm run test:existing`은 모의 편집기에서 같은 주소에 한 번만 저장, 잘못된 대상과 원문 충돌 시 저장 중단, 사진 설명·태그·공개 상태·대표 이미지·발행 시각 보존을 확인했다. 날짜 메타가 없는 화면은 같은 글의 공개 RSS 날짜로 확인한다. 이 검사를 Windows CI와 EXE 빌드 워크플로에도 연결했다.
- 격리된 작업실 화면에서 가져오기 → 문장 수정 → 보관 → 같은 글 다시 선택 흐름을 확인했다. 작업은 한 개로 유지되고 수정 내용이 보존된다.
- 팁 상자의 배경·테두리·여백, 원문 사진과 표지, 표·강조·링크·순서 있는 목록을 화면에서 확인했다. 특수문자 `$&`, `<검토 완료>`도 일반 글자로 보존된다.
- 실제 티스토리 게시글에는 저장·수정 작업을 실행하지 않았다. 모의 편집기 검증은 실제 계정에서의 수정 성공을 의미하지 않는다.
- 실제 로그인 상태의 기존 글 수정 화면은 이번 작업에서 확인하지 못했다. 글 관리나 원문에서 해당 글의 보이는 수정 링크를 찾지 못하거나 저장 화면이 관찰한 구조와 다르면 저장 전에 중단한다.
